Shift Time Tracker

A clock-in, clock-out tool that records work shifts and totals the hours worked.

Why I built it

People who work hourly or shift jobs often reconstruct their hours from memory when payday comes. The Shift Time Tracker lets someone clock in, clock out and see their total hours without a spreadsheet.

It was also a good excuse to learn how browsers handle time, which turns out to be more subtle than it looks.

What it does

  • Clock in and clock out with a running timer
  • A history of completed shifts
  • Totals for hours worked
  • A responsive layout designed for quick use on a phone

How it works

Store timestamps, not counters. The first version of a timer usually adds one to a number every second. That breaks as soon as the tab is closed, the laptop sleeps or the browser throttles background tabs. Instead the app saves the moment the shift started and, on every tick, calculates the elapsed time as the current time minus that start time. The display can be wrong for a second, but the real value never is.

An active shift survives a refresh. The start time of a shift in progress is saved to localStorage. When the page loads, the app checks for it and resumes the timer.

Formatting durations. Shift lengths are stored in milliseconds and only converted to hours and minutes when they are displayed.

function formatDuration(ms) {
  const totalMinutes = Math.floor(ms / 60000);
  const hours = Math.floor(totalMinutes / 60);
  const minutes = totalMinutes % 60;
  return `${hours}h ${String(minutes).padStart(2, "0")}m`;
}

Technical lessons

  • Derive values instead of storing them. Elapsed time and totals are calculated from timestamps, which keeps them consistent.
  • setInterval is not a clock. It drifts and pauses in background tabs, so it should only trigger redraws.
  • Edge cases are the real work. A shift that crosses midnight or a daylight saving change cannot be handled by subtracting two clock times as strings.
  • Small interfaces need big tap targets. A tool used between tasks has to work with one thumb.

What I would improve next

  • Add break tracking that is subtracted from the shift total
  • Add an hourly rate and an estimated pay total
  • Let the user edit a shift when they forgot to clock out
  • Make the app installable and usable offline as a progressive web app
