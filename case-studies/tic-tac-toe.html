Tic Tac Toe

A two-player browser game that tracks the board, alternates turns and detects wins and draws.

18 Feb 2024Solo project: design and development

Open live demo All projects

Why I built it

Tic Tac Toe is small, but it contains the core of every game: state, turns, rules and an end condition. I built it to practise modelling a problem with data instead of hard-coding every case.

What it does

  • Alternating X and O turns
  • Win detection across rows, columns and diagonals
  • Draw detection when the board is full
  • Moves blocked on taken squares and after the game ends
  • A restart button

How it works

The board is an array of nine cells. Index 0 is the top-left square and index 8 is the bottom-right. Each cell holds "X", "O" or an empty value.

Winning lines are data. There are exactly eight ways to win. Rather than eight separate if statements, the lines are listed once and checked in a loop.

const lines = [
  [0, 1, 2], [3, 4, 5], [6, 7, 8], // rows
  [0, 3, 6], [1, 4, 7], [2, 5, 8], // columns
  [0, 4, 8], [2, 4, 6]             // diagonals
];

function checkWinner(board) {
  for (const [a, b, c] of lines) {
    if (board[a] && board[a] === board[b] && board[a] === board[c]) {
      return board[a];
    }
  }
  return board.every(cell => cell) ? "draw" : null;
}

Each click runs the same steps. Ignore the click if the square is taken or the game is over, place the mark, check for a result, then switch the player.

Technical lessons

  • Data-driven logic is shorter and safer. Listing the winning lines was cleaner and less error-prone than writing each case by hand.
  • Game state needs a clear owner. Keeping the board in one array and drawing the screen from it prevented the display and logic from drifting apart.
  • Guard clauses prevent bugs. Early returns for invalid moves kept the main logic short.

What I would improve next

  • Add a computer opponent, starting with random moves and then the minimax algorithm
  • Highlight the winning line
  • Add a score counter across rounds
