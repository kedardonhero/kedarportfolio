Why I built it

Many people only find out where their money went at the end of the month, when it is too late to change anything. I built the Personal Expense Tracker to make spending visible at the moment it happens: add a transaction, and the balance, the list and the chart all update straight away.

I deliberately built it with plain HTML, CSS and JavaScript and no framework or backend. I wanted to understand state, rendering and persistence from the ground up before relying on tools that hide them.

What it does

  • Add and remove income and expense transactions with an amount, category, date and note
  • Running totals for income, expenses and balance
  • A category chart drawn with Chart.js
  • Data saved in the browser so it is still there after a refresh
  • A responsive layout that works on phones and desktops

How it works

One list is the source of truth. Every transaction is an object in a single array. The totals, the table and the chart are never edited directly; they are all rebuilt from that array by a render function. That rule removed a whole class of bugs where the screen and the data disagree.

Saving and loading. After each change the array is converted to a JSON string and written to localStorage. On startup the app reads it back inside a try/catch, so corrupted or missing data falls back to an empty list instead of breaking the page.

function save() {
  localStorage.setItem("transactions", JSON.stringify(transactions));
}

function load() {
  try {
    return JSON.parse(localStorage.getItem("transactions")) || [];
  } catch {
    return [];
  }
}

From transactions to a chart. Chart.js needs labels and values, so the expenses are grouped by category with reduce() and the result is handed to the chart.

function totalsByCategory(transactions) {
  return transactions
    .filter(t => t.type === "expense")
    .reduce((totals, t) => {
      totals[t.category] = (totals[t.category] || 0) + t.amount;
      return totals;
    }, {});
}

Technical lessons

  • State first, interface second. Deciding what the data looks like before drawing anything made every later feature easier.
  • Floating point and money do not mix perfectly. Adding 0.1 and 0.2 in JavaScript does not give exactly 0.3, so amounts should be rounded for display or stored as whole cents.
  • localStorage only stores strings. Everything has to pass through JSON, and anything read back must be treated as untrusted input.
  • Charts keep state too. Creating a new Chart.js chart on the same canvas without destroying or updating the old one causes overlapping, flickering charts.
  • Because there is no backend, data lives on one device. That is a real limitation, and it shaped my next steps.

What I would improve next

  • Add accounts and a backend so the data syncs across devices
  • Export transactions to CSV
  • Add monthly budgets with a warning when a category goes over
  • Support recurring transactions such as rent or subscriptions
